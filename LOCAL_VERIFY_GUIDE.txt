================================================================================
  cashlog.id — PANDUAN IMPLEMENTASI & VERIFIKASI
================================================================================

Dokumen ini menjelaskan setup end-to-end dari nol: akun eksternal, env,
database, deploy, dan checklist uji.

Stack:
  ct-frontend  → Next.js (landing, dashboard, onboarding, settings)
  ct-backend   → Fastify + Baileys (WA) + Google Sheets API
  Supabase     → Auth (email/password + Google OAuth) + profil langganan
  MySQL        → WA session, kategori, budget, Google refresh token
  Google Cloud → OAuth Sheets/Drive (terpisah dari login Supabase)
  Midtrans     → Snap checkout + Subscription API (opsional di dev)
  Resend       → Email welcome & konfirmasi langganan (opsional)

4. SUPABASE AUTH
================================================================================

  4.1 Enable providers (Authentication → Providers):
        - Email          → ON (untuk register/login password)
        - Google         → ON (Client ID/Secret dari Google Cloud)

  4.2 Redirect URLs (Authentication → URL Configuration):
        Site URL:       http://localhost:3000
        Redirect URLs:  http://localhost:3000/auth/callback

  4.3 Catat credentials (Project Settings → API):
        SUPABASE_URL                  → backend + frontend
        anon public key               → NEXT_PUBLIC_SUPABASE_ANON_KEY
        service_role key              → SUPABASE_SERVICE_ROLE_KEY (backend only)


================================================================================
5. GOOGLE CLOUD (SATU OAuth CLIENT — WAJIB SAMA)
================================================================================

  Google login + izin Sheets/Drive memakai SATU OAuth client Google Cloud
  (Client ID/Secret yang sama di Supabase DAN ct-backend/.env).

  Alur user:
    • Daftar/Masuk dengan Google → 1 consent (auth + Sheets scope)
      → refresh token disimpan via /api/sheets/connect-token
      → Sheet dibuat otomatis saat onboarding (bukan saat login)
    • Daftar email → saat onboarding: OAuth Sheets fallback (1 klik Google)

  5.1 Enable APIs:
        - Google Sheets API
        - Google Drive API

  5.2 OAuth client "Web application" (SATU client untuk semua):

    Authorized redirect URIs (tambahkan keduanya):
        http://localhost:3001/api/sheets/oauth/callback
        https://<project-ref>.supabase.co/auth/v1/callback

    → GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET di ct-backend/.env
    → Supabase → Authentication → Providers → Google:
        isi Client ID/Secret YANG SAMA
        (Supabase otomatis minta scope tambahan dari frontend saat login)

  5.3 Testing mode: tambahkan email Anda sebagai Test User di consent screen.

  Catatan: refresh token dari Supabase Google login hanya valid di backend
  jika Client ID/Secret identik dengan GOOGLE_CLIENT_ID di backend.

7. LAYANAN EKSTERNAL (PASANG SAAT SIAP)
================================================================================

  ── 7.1 Midtrans — langganan berbayar ─────────────────────────────────────

    Daftar: https://midtrans.com
    Docs:   https://docs.midtrans.com/docs/snap-snap-integration-guide

    Env backend:
      MIDTRANS_SERVER_KEY=SB-Mid-server-...   # sandbox Server Key
      MIDTRANS_IS_PRODUCTION=false
      MIDTRANS_CHECKOUT_MODE=snap             # snap | recurring

    Webhook URLs (MAP Dashboard → Settings → Configuration):
      Payment Notification URL:
        https://<API_HOST>/api/webhooks/midtrans
      Recurring Notification URL (jika mode recurring):
        https://<API_HOST>/api/webhooks/midtrans/recurring

    Redirect URLs (Finish / Error / Pending):
      https://cashlog.id/settings?payment=...

    Flow user:
      Settings / subscription-expired → Pilih Basic/Pro
      → Redirect ke halaman Snap Midtrans (VA, QRIS, kartu, GoPay, dll.)
      → HTTP notification settlement/capture → langganan aktif +30 hari

    Mode recurring (MIDTRANS_CHECKOUT_MODE=recurring):
      Snap UI khusus recurring → saved token → Subscription API
      → charge otomatis tiap bulan (kartu kredit / GoPay token)

    Tanpa Midtrans + NODE_ENV=development:
      Checkout langsung aktifkan langganan (dev bypass).

    Cancel auto-renewal: Settings → "Batalkan perpanjangan otomatis"

  ── 7.2 Resend — email transaksional ──────────────────────────────────────

    Daftar: https://resend.com
    Verifikasi domain cashlog.id → buat API key

    Env backend:
      RESEND_API_KEY=re_...
      EMAIL_FROM=cashlog.id <noreply@cashlog.id>

    Email yang dikirim:
      - Welcome (setelah register / OAuth pertama kali)
      - Langganan aktif (setelah pembayaran sukses)

    Tanpa Resend: email di-skip, log "[email] Skipped" — app normal.

12. TROUBLESHOOTING
================================================================================

  MySQL connection refused
    → MySQL running, cek MYSQL_* di .env

  Login Google loop
    → Redirect URL Supabase = .../auth/callback
    → NEXT_PUBLIC_APP_URL benar

  API 401
    → User login, NEXT_PUBLIC_API_URL benar
    → Authorization: Bearer <supabase_access_token> wajib di request

  API 429 RATE_LIMITED
    → Terlalu banyak request dari IP yang sama; tunggu Retry-After
    → Pastikan TRUST_PROXY=true jika di belakang reverse proxy

  API 403 SUBSCRIPTION_EXPIRED
    → Normal jika trial habis; bayar atau reset di Supabase

  WA tidak balas
    → Kirim ke chat DIRI SENDIRI
    → Sheet + WA harus terhubung
    → Backend running

  Midtrans checkout gagal
    → Cek MIDTRANS_SERVER_KEY (Server Key, bukan Client Key)
    → Sandbox vs production (MIDTRANS_IS_PRODUCTION)

  Slot anggota keluarga tidak aktif setelah bayar
    → Webhook payment notification diterima?
    → custom_field3 = slots di notification body
    → Dev bypass: kosongkan MIDTRANS + NODE_ENV=development

  Webhook tidak masuk
    → Backend harus HTTPS publik (bukan localhost)
    → Verifikasi signature_key SHA512
    → URL webhook benar di MAP Dashboard Midtrans

  Email tidak terkirim
    → RESEND_API_KEY + EMAIL_FROM
    → Domain verified di Resend
